# ADR-010: Laravel Boost AI Context Integration & Distribution Strategy

## Status
Accepted

## Date
2026-10-22

## Context
As AI-assisted software engineering (using tools like Claude Code, Cursor, Copilot, and VS Code AI agents) becomes central to modern Laravel workflows, the official `laravel/boost` package provides an automated mechanism to discover and feed domain conventions, guidelines, and skills directly into AI agents.

During validation of `x-multibyte/blatui-admin` alongside `anousss007/blatui` and `laravel/boost`, two systemic problems were identified:

1. **Package Distribution Archive Truncation**:
   The package root `.gitattributes` contained `/resources/boost export-ignore`. When Composer installs `x-multibyte/blatui-admin` via dist packages (zipballs generated by GitHub Archive), git automatically omitted `resources/boost/`. Consequently, downstream host applications never received the package's AI skills or guidelines.

2. **Boost Transitive Dependency Isolation**:
   In `laravel/boost`, `ThirdPartyPackage::boostDirectories()` intentionally filters packages by `$package->isDirect()`, preventing transitive (indirect) dependencies from injecting AI prompts or skills. Because host applications typically require `x-multibyte/blatui-admin` directly while `anousss007/blatui` is resolved as a transitive dependency, the underlying `blatui-development` skill is ignored by Boost unless `anousss007/blatui` is explicitly required in the host `composer.json`.

3. **Incomplete AI Context Assets**:
   The package previously only had an unpopulated placeholder `SKILL.md` and lacked a core guidelines template (`resources/boost/guidelines/core.blade.php`), preventing Boost's `boost:install` from seeding the host's `.ai/` directory or prompt context with BlatUI Admin's critical invariants (such as the Zero Duplicate-Alpine rule, Additive CSS/JS, and Pure Prompts).

## Decision
Implement a comprehensive AI context integration and distribution strategy:

### 1. Guarantee AI Asset Distribution via `.gitattributes`
- Remove `/resources/boost export-ignore` from `.gitattributes`.
- Ensure that `resources/boost/` (including all guidelines and skills) is explicitly bundled in all tagged releases and Composer dist archives.

### 2. Dual-Layer AI Context Assets (Guidelines + Skills)
Ship both tiers of AI guidance supported by Laravel Boost:
- **Core Guidelines (`resources/boost/guidelines/core.blade.php`)**:
  Loaded upfront when agents initialize or during `php artisan boost:install`. This template codifies fundamental architectural invariants:
  - 4-tier installer lifecycle (`Diagnostics`, `Actions`, `Wizard`, `CLI Commands`).
  - Zero Duplicate-Alpine rule.
  - Additive W3C/Lightning CSS styling.
  - Code ownership component model (`blatui:add <component>`).
  - Pure `laravel/prompts` UI standard.
  - Essential CLI commands (`blatui:admin --install`, `--dry-run`, `blatui:add`, `boost:update --discover`).
- **Domain Agent Skill (`resources/boost/skills/blatui-admin-development/SKILL.md`)**:
  On-demand workflow skill invoked when an agent installs, extends, or troubleshoots BlatUI Admin features, providing concrete Blade examples and step-by-step guidance.

### 3. Adaptive Installer AI Context Onboarding
- In `InstallWizard::executePipeline()`, detect if `laravel/boost` is present in the host application via `Composer\InstalledVersions::isInstalled('laravel/boost')`.
- If present, output a friendly prompt advising the developer to run `php artisan boost:update --discover` to synchronize guidelines and skills into their AI agents.

### 4. Transitive Dependency Coexistence Strategy
- Document clearly that for AI agents to natively discover both the admin panel skill (`blatui-admin-development`) and the lower-level Blade component skill (`blatui-development`), host applications should promote `anousss007/blatui` to a direct dependency (`composer require anousss007/blatui`).
- In addition, `blatui-admin-development` guidelines and skills must explicitly encompass basic `<x-ui.*>` usage instructions so agents remain effective even before `anousss007/blatui` is explicitly promoted.

## Alternatives Considered

### 1. Storing Boost Guidelines in Host `.ai/` Exclusively
- **Pros**: Keeps the package vendor directory minimal.
- **Cons**: Requires the installer to copy files into user space on every install; cannot benefit from automatic Boost vendor discovery (`ThirdPartyPackage`) and version synchronization via `boost:update`.
- **Verdict**: Rejected.

### 2. Re-exporting `anousss007/blatui` Guidelines Under `blatui-admin`
- **Pros**: Automatically bypasses Boost's transitive dependency filter.
- **Cons**: Duplicates code across packages, creates maintenance drift when `anousss007/blatui` updates its guidelines, and violates single-source-of-truth principles.
- **Verdict**: Rejected. Promoting `anousss007/blatui` in the host project is idiomatic and clean.

## Consequences
- **Positive**:
  - `x-multibyte/blatui-admin` becomes a first-class AI-ready package in the Laravel ecosystem.
  - AI coding assistants working in host projects automatically understand and obey the package's critical invariants (preventing duplicate Alpine installations, broken CSS imports, or invalid component scaffolding).
  - Release archives correctly contain the required resources without accidental omission.
- **Negative**:
  - The package maintainer must maintain `resources/boost/` assets alongside code changes whenever architectural patterns or CLI options evolve.
