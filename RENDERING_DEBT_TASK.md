# Task: Clear the Rendering Architecture Debt (Steps 1-4)

Repository: `/laravel/packages/x-multibyte/blatui-admin`
Branch: `feature/rendering-debt` (already created, checked out)

## Context

The package documents a modern rendering architecture in `AGENTS.md` and
`docs/superpowers/specs/2026-09-27-rendering-architecture-design.md`:

- PHP classes are strictly ViewModels / DTOs, never HTML string builders
- All DOM markup and Tailwind/Alpine directives live in `resources/views/*.blade.php`
- Rendered components implement `Illuminate\Contracts\Support\Htmlable`
- Blade renders them with native escaping `{{ $component }}`
- Zero `{!! !!}` raw output

An audit found the code only partially implements this contract. This task
closes the gap. Everything here is a **correctness fix** — no public API
changes, no new features.

## Ground rules

- Namespace is `BlatUI\Admin`. PHP 8.3+, `declare(strict_types=1);` required.
- `composer test` must end fully green: PHPStan 0 errors, Pint clean,
  Pest 109+ passing, type coverage 100%.
- Work only on the current branch. Do not touch `main`.
- Do NOT add new dependencies.
- Do NOT reformat unrelated code.
- One commit per numbered step below, with the given message.

## Step 1 — Fix the failing-green security tests FIRST

**Why first:** some tests currently assert that unescaped markup is preserved.
If you fix the code without fixing these, the suite goes red and you will
think you broke something. This step must land before Step 2.

### Step 1a — `tests/Security/LayoutContentEmpiricalVerificationTest.php`

Read the test named `2.2. Content::render() with nested rows and columns
preserves full grid HTML markup`. It asserts that HTML generated by
`Layout\Row` / `Layout\Column` survives into the output. That behavior is the
bug we are fixing, so the assertion must be inverted.

Rewrite it to assert **escaping** instead of preservation:
- Build a `Layout\Row` whose `class` contains a payload such as
  `grid"><script>alert(1)</script>`
- Assert the rendered output does NOT contain the raw `<script>` substring
- Assert it DOES contain the entity-encoded form `&lt;script&gt;`

## Step 2 — Escape `Layout\Row` and `Layout\Column`

**Files:** `src/Layout/Row.php`, `src/Layout/Column.php`

### `src/Layout/Row.php`

`Row::render()` currently does:

```php
$html = "<div class=\"{$this->class}\">";
```

`$this->class` is interpolated with no escaping. Escape it with
`htmlspecialchars($value, ENT_QUOTES, 'UTF-8')`, matching the existing
convention used in `src/Grid/Column.php:365` and
`src/Grid/Filter/Field.php:306`.

### `src/Layout/Column.php`

`Column::buildClasses()` produces class strings from:
- the fixed literal `col-span-12`
- `$breakpoint` — an **array key** supplied by the developer
- `$span` — an int, but interpolated into a string

Escape the `$breakpoint` segment when building the class string. Verify the
int path still renders exactly as before (e.g. `md:col-span-6`).

Also check `Column::render()`: it renders `$this->contents` through
`Support\Helper::render()`. Do not change `Helper` in this step — just confirm
and report whether plain strings passed to it are escaped. Report the finding
in your final summary; do not fix it here.

Commit: `fix(layout): escape dynamic class names in Row and Column renderers`

## Step 3 — Remove the ineffective ViewComposers

**Files:** delete `src/View/Composers/GridComposer.php`,
delete `src/View/Composers/LayoutComposer.php`,
modify `src/AdminServiceProvider.php`,
delete their tests from `tests/Security/XssRenderingTest.php`.

### Why

The design spec 2.3 asks for a ViewComposer "gatekeeper". The implementation
does the opposite of what it claims: `sanitize()` converts plain strings into
`HtmlString`. Blade's `{{ }}` calls `toHtml()` on `HtmlString` and does NOT
escape. So the composer pre-escapes, Blade then skips escaping, and the two
operations cancel out — the result is identical to having no composer at all,
while the class name implies a guarantee it does not provide.

It also provides no defense in depth: `sanitize()` returns any non-string,
non-array, non-Htmlable object untouched, so `Row` / `Column` objects pass
straight through to Blade.

Blades `{{ }}` IS the gate. Remove the redundant layer and correct the spec.

### What to do

1. Delete both composer classes and their directory if empty.
2. Remove the `registerViewComposers()` call and method from
   `AdminServiceProvider`, plus the now-unused imports.
3. Remove the composer-related tests from `XssRenderingTest.php`. **Keep** the
   first two tests (`Content implements Htmlable and Renderable contracts`,
   `Content layout renderFallback escapes title and description`) — they are
   valid and independent of the composers.
4. Update `docs/superpowers/specs/2026-09-27-rendering-architecture-design.md`
   section 2.3 to state that Blade native escaping is the security boundary
   and that no additional ViewComposer layer is required. Use precise software
   engineering language consistent with the rest of the document.

Commit: `refactor(security): remove ineffective ViewComposer layer, rely on Blade escaping`

## Step 4 — Eliminate the remaining `{!! !!}` raw output

**Files:** `resources/views/grid/table.blade.php`,
`resources/views/layouts/fallback.blade.php`,
`resources/views/partials/header.blade.php`

Four raw-output sites remain (AGENTS.md claims they were already removed):

| File | Line | Current |
| --- | --- | --- |
| `grid/table.blade.php` | ~106 | `{!! $row->renderCheckbox() !!}` |
| `grid/table.blade.php` | ~118 | `{!! $row->renderActions() !!}` |
| `layouts/fallback.blade.php` | ~12 | `{!! $row->render() !!}` |
| `partials/header.blade.php` | ~37 | `{!! $navbarLeft !!}` |
| `partials/header.blade.php` | ~68 | `{!! $navbarRight !!}` |

### The `Row` problem you must solve first

`Grid\Row::render()` does **not** render a row of data. It returns
`renderActions()` — the action button bar. That is why it is used with `{!! !!}`.
Its `toHtml()` therefore means "actions HTML", not "row HTML", which violates
the `Htmlable` contract's intent and makes `{{ $row }}` misleading.

Resolve this properly:
- Extract the checkbox markup and the actions markup out of
  `src/Grid/Row.php` into Blade partials under
  `resources/views/grid/partials/`.
- Keep `Grid\Row` as a data holder. It should expose state and accessors
  (`getKey()`, `isActionsDisabled()`, `isShowDisabled()`, `isEditDisabled()`,
  `isDeleteDisabled()`, `isQuickEditDisabled()`, `getResource()`, plus
  `getActions()` returning the ordered action list), NOT pre-rendered HTML.
- The Blade partials then render the markup and use `{{ }}` throughout.

### The `header.blade.php` navbar case

Inspect what `$navbarLeft` / `$navbarRight` actually are. If they are
`Htmlable` / `HtmlString`, `{!! !!}` is redundant — `{{ }}` works identically.
Convert them to `{{ }}`. If they are plain strings that are intentionally
already-rendered HTML, say so in your final report and convert them anyway,
because the resulting HTML must be produced by a Blade view, not by a
string-concatenating PHP class.

### `fallback.blade.php`

`{!! $row->render() !!}` iterates `Layout\Row` objects. Once Step 2 has
escaped the class attribute, this is safe, but it still violates the
"no PHP string builders" rule. Convert it so the markup lives in Blade.

### Constraints

- The rendered output must stay **functionally identical**: same CSS classes,
  same Alpine directives (`x-model="selectedRows"`, `@click`, `x-data`, and
  the `toggle-grid-filter` window event), same `name="_row_id[]"` checkbox
  contract, same form field names.
- `tests/Unit/GridRowTest.php` has ~12 tests asserting on `renderActions()`
  and `renderCheckbox()`. Decide: keep those methods as thin delegations to
  the new Blade partials, OR update the tests to render the partial directly.
  Prefer keeping the methods if it can be done without reintroducing string
  building in the PHP class. **Explain your choice in the final report.**
- After this step, `grep -rn '{!!' resources/views` must return nothing.

Commit: `refactor(views): migrate remaining raw Blade output to native escaping`
